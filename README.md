# AI-детектив — лабораторная работа 6

Исследование ответов одной LLM на вопросы по вымышленному досье. Сравниваются полный контекст (A), BM25 top-15 (B) и те же 15 утверждений, сгруппированные по p-adic ветвям (C).

|---|---|

Все участники должны проверить эталоны и понимать архитектуру целиком.

## Данные и режимы

`data/` содержит 10 документов (более 5 000 слов), 37 атомарных утверждений, 12 вопросов и 28 подготовленных стресс-кейсов: 12 перестановок, 4 удаления посылки и 12 добавлений противоречия. Для каждого кейса зафиксирован ожидаемый статус. `src/data_io.py` проверяет уникальность ID, ссылки и дословное вхождение `evidence` в документ.

- **A** передаёт все документы в исходном порядке и реестр утверждений с ID, чтобы модель могла сослаться на доказательства.
- **B** выбирает не более 15 утверждений BM25.
- **C** использует тот же набор ID, группирует по пути `[a₀,a₁,a₂]` при `p=3` и сортирует события по времени внутри ветви.

В стресс-кейсе меняется один фактор. Перестановка документов использует seed 42. Удаление убирает утверждение из реестра и его дословный фрагмент из документа. Добавление противоречия добавляет новый документ и новое утверждение. Каждый запрос сохраняет полный текст фактически переданного контекста и состав документов и утверждений.

## Установка

Требуется Python 3.11+ и доступ к DeepSeek API. Имя модели `deepseek-flash`, адрес API и формат JSON описаны в [документации DeepSeek](https://api-docs.deepseek.com/en/) и [руководстве по JSON Output](https://api-docs.deepseek.com/guides/json_mode/).

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pytest -q
```

Сервисный ключ можно задать в окружении, в скрытом поле Streamlit или через `--ask-key`. Его не следует сохранять в репозитории:

```bash
export DEEPSEEK_API_KEY='ваш ключ'
```

По умолчанию используется `deepseek-flash`; модель можно указать в интерфейсе или через `--model`. API вызывается с одним сохранённым промптом из `prompts/system.txt`, одной моделью и одинаковыми параметрами для всех режимов. Режим рассуждений отключён, ответ запрашивается как JSON Object и затем проверяется локально по схеме и логическим правилам. Ключ в файлы результатов не записывается; необработанный ответ сохраняется для ручного анализа.

## Интерфейс и полный эксперимент

```bash
.venv/bin/streamlit run app.py
```

В интерфейсе можно загрузить четыре JSONL файла, ввести DeepSeek API key в скрытое поле, выбрать вопрос, режим, подготовленный стресс-кейс, увидеть контекст, p-adic ветви, ответ, уверенность, доказательства и метрики сохранённых результатов. Прогон всех режимов делает 120 запросов: 36 исходных и 84 стрессовых; можно выбрать часть режимов. Каждый ответ сразу добавляется в `results/runs.jsonl`; файл исключён из Git.

Запуск без интерфейса:

```bash
.venv/bin/python run_experiment.py --model deepseek-flash
```

Для скрытого ввода ключа без переменной окружения добавьте `--ask-key` в терминале. Для быстрой проверки исходных 36 ответов добавьте `--baseline-only`. Невалидный ответ модели сохраняется с исходным JSON и учитывается как ошибка в общей точности статуса. Ошибку доступа к API можно повторить с тем же `run_id`; уже полученные ответы, включая невалидные, не запрашиваются повторно. Запуск без `--run-id` получает новый идентификатор; результаты разных прогонов не смешиваются.

При временном сбое API можно продолжить тот же прогон:

```bash
.venv/bin/python run_experiment.py --ask-key --run-id RUN_ID
```

Полный прогон `deepseek-flash` завершён: 120/120 ответов, `run_id=065b6c66abda446fa977334da35cd39e`. Полные ответы и фактически переданные контексты сохранены в `results/deepseek_flash.jsonl.gz` (архив включён в Git). Локальный накопительный файл `results/runs.jsonl` исключён из Git. Прежний частичный прогон Groq вынесен в `GROQ_BC_ARCHIVE.md` и не входит в метрики DeepSeek.

## Отчёт

Итоговый PDF уже создан из полного реального прогона. Его можно воспроизвести из архива:

```bash
.venv/bin/python generate_report.py --results results/deepseek_flash.jsonl.gz --run-id 065b6c66abda446fa977334da35cd39e --output report.pdf
```

Генератор отказывается строить отчёт по неполному прогону, ошибкам API или тестовой модели. В отчёте приведены метрики A/B/C, устойчивость к трём стресс-тестам, уверенность при недостатке данных, ограничения эксперимента и вклад участников. Итоговые интерпретации и эталоны следует проверить всей командой до сдачи. `report.pdf` содержит только реальные измеренные результаты.
